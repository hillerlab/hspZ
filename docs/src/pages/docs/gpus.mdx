## Worker model

`--gpus W` creates up to W workers and assigns complete reference bins by
deterministic longest-processing-time scheduling. Every worker runs all query
bins against the reference bins it owns. More workers than reference bins
leave workers idle; more workers than devices time-slice a device and are a
correctness configuration, not a speed configuration.

GPU completion order never controls output order. Each result carries its
`WorkUnit.ordinal`, and the emitter replays those ordinals in the planned order.

## Seeder policy

| workers | default query seeder |
| ---: | --- |
| 1 | CPU, with pinned asynchronous upload when supported |
| more than 1 | device |

For controlled measurements only:

```bash
HSPZ_DEVICE_SEEDS=0 hspZ run ...  # force CPU
HSPZ_DEVICE_SEEDS=1 hspZ run ...  # force device
```

## Runtime tuning knobs (0.0.5)

Every knob is exact: every mode produces the same HSP set and the same bytes.

| variable | default | what it does |
| --- | --- | --- |
| `HSPZ_REF_BUCKETS=auto\|1\|0` | `auto` | Reference-locality bucketing before the score gate. It wins where lower DRAM traffic lets a power-capped GPU raise its clock (L4: −6.5% whole-genome wall) and loses where the card already runs near its boost clock (RTX 4090: +3.7%). `auto` measures both paths per engine in blocks of ≥3 s, discards each block's first second, and keeps the faster one; `--time` prints the blocks and the decision. Cards whose L2 cannot hold the smallest window (T4) stay off. |
| `HSPZ_REF_BUCKET_SHIFT=<16..31>` | derived from L2 | Pins the bucket window size (implies on). |
| `HSPZ_CHUNK_WALK=full` | sparse | Restores the pre-0.0.4 chunk walk that copied the whole cumulative hit array per seed batch (rollback only). |
| `HSPZ_UNIT_PARTITION=auto\|0\|1` | `auto` | Splits the frozen plan's work units across workers by count quotas when every device the run uses is the same class and each worker has its own device (W=1, time-sliced workers and mixed classes keep whole-bin ownership); output is unchanged. −11.9% seed-and-filter wall on 2× RTX 4090 (1,400 → 1,233 s) and −5.1% on 4× RTX 4090 (718 → 681 s) at `MAX_HITS=16,711,680`. |

## Many queries against one reference

`--query-list` runs every listed query FASTA in one process:

```bash
hspZ run \
  --reference ref.2bit \
  --query-list queries.txt \
  --output OUT \
  --gpus 1
```

`queries.txt` holds one query path per line (blank lines and `#` comments are
ignored). Each reference bin is built and uploaded once instead of once per
query, while every query keeps its own plan, cap, seed batches, dedup scopes
and `-D` history, so its output under `OUT/000001/`, `OUT/000002/`, … is
byte-identical to a standalone run. `-Z` writes one archive per job;
`OUT/queries.tsv` maps job → path, size, sha256, blocks, units, HSPs and
completion. A failing job aborts the batch (partial outputs may remain).

In 0.0.6 batch mode requires W=1 (`--gpus 1`), all jobs must plan to identical
reference bins, `-B 0` is rejected as a layout, and `--kegalign-bins` and
`--from-manifest` are rejected. Bin-major order delays the first result: check
`OUT/queries.tsv` rather than waiting on the first job directory.

## Choosing `-B`

The default 500 Mbp preserves the KegAlign-matched one-GPU digest; hspZ never
changes it merely because `--gpus` changed.

When a new digest is acceptable, start near the coarsest target that yields at
least one reference bin per worker:

```text
--seq-block-size ≈ total reference bp / W
```

On one measured 4× RTX 4090 host, two bins per worker (`≈ total / 2W`) was 3.2%
faster than one bin per worker. Treat that as a per-machine refinement, not a
new default. Finer bins multiply work units and can be much slower.

Use `--query-block-size` to avoid splitting the query merely because the
reference needs more bins. Any changed block geometry gets its own frozen
digest.
