## Files

The default sink creates a directory containing non-empty files named:

```text
tmp<n>.block<query-bin>.r<reference-bin>.plus.segments
tmp<n>.block<query-bin>.r<reference-bin>.minus.segments
```

`n` is the one-based query-interval number. `-D` adds `.split1`, `.split2`, …
before `.segments`; `-Z` writes the same logical entries directly into one
reproducible `.tar.gz` archive with pinned mtimes, `<output>.tar.gz` unless a
path follows `-Z`.

With `--query-list`, each job writes this layout into its own directory,
`OUT/000001/`, `OUT/000002/`, … (or its own `OUT/000001.tar.gz`, … with `-Z`),
and `OUT/queries.tsv` lists the jobs once all of them have finished (see
*GPUs and seeding*).

## Paired mode

`--paired -S plus` compares record *i* of `-r` only with record *i* of `-q`.
It is meant for many small, independent region pairs, such as chain gaps. The
two files must hold the same record names in the same order, and each query
record must fit one seed chunk (`-C`) and one LASTZ interval (`-I`).

The run writes one file, `OUT/paired.segments`, and creates it even when it is
empty. For every pair, its lines are byte-identical to what a standalone
`hspZ run -S plus` of that pair's two records writes, with the same scoring,
seed and `--max-hits` flags. Pairs appear in input order, and coordinates are
relative to each record. `--step` must be 1. Pass minus-strand pairs with the
query record already reverse-complemented.

`-D`, `-Z`, `--query-list`, `--index`, manifests, `--dump-plan`,
`--dump-raw`, `--hit-stats`, `--cpu-only`, `-B 0` and `--gpus` above 1 are
rejected with `--paired`. `-B` caps the bases per batch on each side; batches
are also sized to fit the GPU, and the output does not depend on either.
`assets/tests/paired-identity.sh` checks the per-pair claim.

## Record format

Each tab-separated line has eight fields:

```text
reference  ref_start  ref_end  query  query_start  query_end  strand  score
```

Coordinates are chromosome-relative, one-based, and inclusive at both ends.
Minus-strand records use the reverse-complement query frame and are emitted in
reverse anchor order, matching KegAlign/LASTZ expectations.

## Ordering and deduplication

Within each `MAX_HITS` chunk, accepted GPU HSPs are stably sorted by diagonal,
adjacent contained/duplicate records are removed with KegAlign's previous-input
semantics, and survivors are stably sorted into LASTZ query-major order before
coordinate conversion.
